# Pokémon card tracker

Open Investments → Pokemon Cards. The tracker is a separate list for selected high-value cards and PSA slabs. Existing holdings, portfolio valuations and net-worth calculations still use the manually entered portfolio value. No reference prices are added to portfolio totals.

Add a card with its name, set, card number, language, owned grade (raw or PSA 1–10), optional certificate number and variant/condition notes. Add separate entries for distinct variants or individual slabs. Certificate links open PSA; the app does not automatically verify certificates.

The add-card flow starts with a language selector, followed by a searchable TCGdex set list and card-number/name lookup within the selected set. An exact number match fills the catalog name and image automatically; leading zeros and printed totals such as `004/102` are accepted. Otherwise select a result to confirm its identity. Changing language or set clears the previous identity. Catalog requests are cached for the session and canceled when the selection changes. No API key is required. Language and set coverage varies, and manual entry remains available for missing cards. Existing manually entered cards remain editable without a catalog match. Catalog identity is separate from the manually recorded market prices.

Simplified Chinese lookup uses [PTCG-CHS-Datasets](https://github.com/duanxr/PTCG-CHS-Datasets), a community source of Pokémon Shanghai card data. It replaces the empty TCGdex Gem Pack reference entries with actual set cards, printed names, full collector numbers, rarities and source images. The browser fetches the original JSON directly and caches compact card identities in memory; the large original data and images are not bundled, copied or redistributed in the project. The initial download may take up to a minute. The source limits use to personal non-commercial, academic or research purposes and prohibits redistribution; do not reuse this integration for commercial distribution without securing the appropriate permissions. A failed load shows a retry option instead of pretending a reference entry is a searchable card list.

Set counts for Chinese collections reflect the actual available source printings. Full printed fractions are significant: CBB6C `1107/07` matches `11 07/07`, 变隐龙, rarity ★★★. A different denominator must not silently resolve to that card. If several source entries share a number, choose the image and rarity; the app preserves their distinct stable IDs. An optional PokéAPI species lookup supplies the English Pokémon name (Kecleon in this example), while the printed Chinese card name remains authoritative. An English species name does not translate every trainer name or card suffix. Saved cards retain source identity, number, image, rarity and the English species name if resolved before saving. Existing manually added cards can be edited and switched back to catalog lookup to attach their correct identity. The grade selector defaults to Raw / ungraded; PSA certificate fields appear only for PSA grades.

Prices are fetched automatically from free, public read endpoints. The manual price-entry form has been removed. Guardian TCG's public search and card-detail feeds supply raw and any explicitly published cached PSA 8/9/10 quotes for exact English or Simplified Chinese matches. Chinese Gem Pack codes map to the corresponding named set; name, game/print language and collector number must also match. Zero, null, mismatched and ambiguous results never become a price. The detail snapshot takes precedence over search snippets, which can be stale. Provider quotes are market estimates, not verified individual sale records. Cached PSA quotes lack source dates and sale samples; the UI says so. No PSA price is inferred from a raw value or another grade. Unavailable grades remain unavailable.

TCGdex supplies available raw Cardmarket trend and TCGplayer market fields for catalog-identified cards in covered languages. Each finish/variant is shown separately, with the source currency and timestamp. Chinese source IDs must never be used to fetch an English printing. These integrations require no account, paid subscription, API token, scraping of protected pages, or browser challenge bypass. They use public endpoints and may change or become unavailable. Automatic queries go through `/api/pokemon/market`, wired into Vite development and the existing Cloudflare application Worker. The separate reminder worker is unrelated. Source hosts are fixed; caller URLs and credentials are not accepted.

The tracker fetches after adding a card or opening the section, offers **Refresh market**, and refreshes every 30 minutes while the section is mounted and the tab is visible. The server caches successful identities for 30 minutes and empty results for one minute. The UI captures the latest observed snapshot per day, retaining up to 90 snapshots in separate browser storage keyed to the public card identity. This is observed tracking history, not backfilled historical transactions. Automatic snapshots currently stay on this device and are not included in the card-list JSON backup or account sync. Failed fetches retain the last successful quote, visibly report the error and preserve the previous fetch date.

Older manually entered observations, if any, are preserved separately below automatic market prices. Comparison tiles for those historical records use the latest observation per source for each grade, currency and price type. Currencies are not converted or combined.

Data is saved to browser storage scoped to the signed-in account (or a separate guest key). **Backup JSON** downloads the full card list and price history; this is a backup export, not an import feature. To enable cross-device sync, run `supabase_pokemon_cards_schema.sql` in the project's Supabase SQL editor. Row-level security restricts each watchlist to its owner. Until that table is available, the UI reports device-only storage. Failed syncs preserve local changes and flag them as pending so a reload does not overwrite them with older cloud data; save an entry again to retry. Concurrent edits on different devices use the last saved watchlist, so back up before switching devices with pending edits.

Validation: `node scripts/test-pokemon.mjs`, `node scripts/test-pokemon-browser.mjs`, `node node_modules/typescript/bin/tsc --noEmit`, and `npm.cmd run build`.
Set `POKEMON_LIVE_CATALOG=1` when running the unit-test command to verify CBB6C and the example number against the current public source. The default tests and browser checks use small synthetic fixtures and do not redistribute the dataset.
Set `POKEMON_LIVE_MARKET=1` to verify the exact CBB6C market match against the free Guardian TCG feed. Tests cover wrong language/set/number/name rejection, ambiguous printings, absent grades, request validation, cache reuse, search/detail discrepancies and preserving displayed quotes on source failure.
